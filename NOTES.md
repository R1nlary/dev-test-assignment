# Заметки

## Что сделано

- Распределение заказов: исправлен расчёт расстояния, добавлены правила `pickup_point` и `city`, дневной лимит по времени Алматы, повторное распределение без увеличения нагрузки и два API-эндпоинта.
- Запись к мастеру: исправлена проверка пересечения интервалов, добавлены свободные слоты с учётом перерывов, записей и текущего времени, проверка телефона, создание и отмена записи. Одновременные бронирования обрабатываются очередью по `masterId`.

## Допущения

- Алматы — UTC+5 без перехода на летнее время.
- При переполнении филиала выбирается ближайший доступный филиал магазина среди всех городов. Без координат запасной филиал не выбирается.
- Отменённые записи не занимают время. Повторная отмена возвращает ту же запись.
- Данные хранятся в памяти и теряются после перезапуска.

## Несколько серверов и PostgreSQL

Для распределения заказов нужен уникальный индекс по `order_id`. Выбор филиала и увеличение дневной нагрузки должны выполняться в одной транзакции с блокировкой строки лимита филиала на дату (`SELECT ... FOR UPDATE`).

Очередь бронирований в памяти работает только в одном процессе. Для нескольких серверов нужно ограничение пересечения активных интервалов одного мастера в PostgreSQL (exclusion constraint). Создание записи выполняется в транзакции, конфликт возвращает `409`.

## Что осталось

Валидация и бизнес-логика находятся в HTTP-обработчиках; их можно вынести в отдельные функции. Для эксплуатации нужны постоянная БД, авторизация и логирование.
